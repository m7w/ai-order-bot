# 🤖 AI Order Assistant — Telegram-бот для автоматизации приёма заказов

Прототип сервиса для автоматической обработки входящих заявок от клиентов в свободной форме. Бот извлекает из неструктурированного текста список товаров, количество, адрес доставки и контактный телефон, превращая диалог в строгий JSON-объект, готовый для передачи в CRM или БД.

## 🎯 Решаемая бизнес-задача
Клиенты часто пишут заявки в произвольном формате (*«Привет, мне бы 2 монитора Dell и кронштейн, привезти завтра на Первомайскую 15»*), забывая указать телефон или точное количество. 
Бот берет на себя первичный разбор заявки:
1. Валидирует наличие обязательных полей (товары, адрес, телефон).
2. Если данных не хватает — **сам задает уточняющий вопрос**, удерживая контекст диалога.
3. Когда все данные собраны — формирует валидную структуру заказа.

## 🛠 Стек и архитектурные решения
* **LLM & Structured Outputs:** Используется `gpt-4o-mini` (через OpenAI-совместимый API / OpenRouter) со строгой JSON-схемой (`Pydantic` / `JSON Schema`). Это гарантирует, что модель вернет предсказуемый формат данных без лишнего текста, исключая ошибки парсинга на бэкенде.
* **Две реализации в репозитории:**
  1. **Классический сервис (`bot.py` + `ai_parser.py`):** Асинхронный бот на `aiogram 3` + `AsyncOpenAI` + `Pydantic`. Контекст диалога хранится в `FSMContext` (в продакшене легко переключается на `RedisStorage`).

## 🚀 Быстрый запуск (локальная версия)

1. Клонируйте репозиторий и установите зависимости:
   ```bash
   git clone <ссылка_на_ваш_репозиторий>
   cd order_bot
   pip install -r requirements.txt
   ```

2. Скопруитй `.evn.example` в файл `.env` в корне проекта и подставте свои значения:
   ```env
   BOT_TOKEN=ваш_токен_от_BotFather
   OPENAI_API_KEY=ваш_api_ключ
   OPENAI_BASE_URL=https://openrouter.ai/api/v1
   LLM_MODEL=openai/gpt-4o-mini
   ```

3. Запустите бота:
   ```bash
   python bot.py
   ```

## 🛡 Обработка граничных случаев и масштабирование
* **Отказоустойчивость:** Сетевые запросы к LLM обернуты в обработку исключений (`APIError`). При недоступности API клиент получает корректное уведомление, а заявка не теряется (предусмотрен fallback на менеджера).
* **Контроль стоимости и задержек:** Использование `gpt-4o-mini` с `temperature=0.1` обеспечивает время ответа 1–1.5 сек и минимальную стоимость обработки (~$0.0001 за диалог).
* **Дальнейшее развитие:** Подключение Webhook в 1С / Битрикс24 / AmoCRM при успешной валидации заказа, интеграция с каталогом товаров (MCP или Function Calling) для проверки остатков.
